# 楽配くんまわりの自動化 — ノウハウと振り返り

別のPCで**楽配くんの別の自動化**（例：配達資料出力）をするときに参照するためのメモです。  
言語選定・設計の教訓・振り返りをまとめています。

---

## 1. どんな自動化に向いているか

- 楽配くん10は**Accessベース**の業務アプリで、ウィンドウ構造が特殊
- **座標ベースのUI操作**（クリック・キー送信）が現実的
- 制御用APIや公式の自動化インターフェースは想定していない前提

### ★ Access アプリの MDI 構造（重要）

楽配くん10は **MDI（Multiple Document Interface）** 構造：

```
┌─ 親ウィンドウ「楽配くん10」─────────────┐
│                                          │
│  ┌─ 子ウィンドウ「メインメニュー」───┐  │
│  │  基本処理  集計処理  特殊処理      │  │
│  │  ...                               │  │
│  └────────────────────────────────────┘  │
│                                          │
└──────────────────────────────────────────┘
```

**注意点：**
- `WinMove` は**親ウィンドウ「楽配くん10」**に対して行う（子ウィンドウを移動しても効かない）
- `WinGetTitle("A")` は親ウィンドウのタイトルを返す
- 子ウィンドウ（メインメニュー、基本処理など）の存在チェックは `WinExist("メインメニュー")` で行う
- **子ウィンドウのタイトル**で現在の画面を判定する（メインメニュー、基本処理、特殊処理など）

## 2. 使う言語・ツール（おすすめ）

| 選択肢 | 向いていること |
|--------|----------------|
| **AutoHotkey v2 (AHK v2)** | デスクトップのクリック・キー送信・ウィンドウ検出に最適。軽い。**楽配くんのような業務アプリの自動操作に適している。** |
| PowerShell + UI Automation | 可能だが、Access系は要素取得が難しく、座標に落ちることが多い |
| Python + pyautogui | 座標クリックはできるが、AHKより導入・配布が重い |

**結論：楽配くんの画面操作自動化は AutoHotkey v2 でやるのがおすすめ。**

---

## 3. うまくいった点（今回の復元自動化で）

- **手動座標キャプチャ方式** … 初回にユーザーがマウスで位置を教え、座標をファイルに保存。ウィンドウ構造に依存しない。
- **ログ機能** … 実行日時・成功/失敗・スキップ理由をテキストに残す。不具合時の切り分けがしやすい。
- **設定GUI** … 自動確認ON/OFF・予約時刻・「起動中はスキップ/そのまま実行」などをGUIで変更できる。
- **柔軟な設定** … 自動確認・スケジュール・PCオフ時・使用中時の挙動をINIで保持。

## 4. だめだった点・反省点

| 問題 | 原因 | 反省 |
|------|------|------|
| WinGetPos / WinGetClientPos で座標取得失敗 | Accessアプリの特殊なウィンドウ構造を想定していなかった | **最初から手動座標キャプチャを前提にすべきだった** |
| MouseClick が効かない | SendMode の違いを考慮していなかった | 最初から `SendMode "Event"` と「移動→待機→クリック」の ReliableClick 相当を使うべきだった |
| SetTitleMatchMode "Substring" エラー | AHK v1 と v2 の構文の違い | AHK v2 の公式ドキュメントを事前に確認すべき |
| DropDown vs DDL エラー | 同上 | 同上 |
| 座標ファイルの改行でパース失敗 | FileAppend の改行位置が不揃い | 1行1エントリなど、フォーマットを最初から統一すべき |
| **ウィンドウが移動しない** | AccessはMDI構造。子ウィンドウ「メインメニュー」を `WinMove` しようとしていた | **親ウィンドウ「楽配くん10」を移動する必要がある** |
| **メインメニュー判定が効かない** | `WinGetTitle("A")` は親ウィンドウのタイトルを返す | 子ウィンドウの存在は `WinExist("メインメニュー")` でチェック |
| **座標が毎回ズレる** | 座標取得時と実行時でウィンドウ位置が異なった | 座標取得も実行も**同じ条件（左上0,0に移動後）**で行う |
| **INIファイルが壊れる** | `FileAppend` で追記すると同じキーが重複 | `IniWrite` で上書き方式にする（INI形式推奨） |

## 5. もっと早くたどり着くためのアドバイス

1. **最初に「対象アプリの特性」を確認する**
   - 例：「楽配くん10はAccessアプリですか？」「ウィンドウは通常のWin32ですか？」
   - 特殊なアプリは座標取得が難しいと想定し、**手動キャプチャ方式を第一候補にする**。
   - **MDI構造か確認する**：親ウィンドウと子ウィンドウが別々にある場合、操作対象を間違えやすい。

2. **最初から堅牢な実装にする**
   - 試行した順：MouseClick → CoordMode変更 → WinGetPos → WinGetClientPos → 手動キャプチャ  
   - **最初から「手動キャプチャ + SendMode Event + ReliableClick（移動→待機→クリック）」**で設計すると試行回数を減らせる。

3. **座標取得と実行の条件を揃える**
   - ウィンドウを移動するなら、**座標取得時も実行時も同じ位置**に移動してから操作する。
   - 座標取得時だけ移動しない、または実行時だけ移動する、という不一致があると座標がズレる。

4. **エラー時のスクリーンショットを早めに共有する**
   - メッセージ内容だけでなく、画面キャプチャがあると原因特定が速い。

5. **AHK v2 の構文を事前に確認する**
   - v1 と v2 で違う部分（SetTitleMatchMode、DDL、など）でハマりやすい。

6. **設定・座標ファイルはINI形式で保存する**
   - `FileAppend` で追記すると重複やパースエラーが起きやすい。
   - `IniWrite` / `IniRead` なら同じキーは自動で上書きされる。

---

## 6. 次回への教訓（あなた・依頼者へ）

- **「座標が必要なUI自動化」は最初から手動キャプチャ方式を提案する** — 特にAccess・古いアプリ・業務ソフト。
- **エラー画面のスクリーンショットを早めに共有する** — 問題の特定が速くなる。
- **「うまくいかない」だけでなく「何が起きたか」を伝える** — 例：カーソルは動いたか、クリックは効いたか。

---

## 7. 安全対策（復元スクリプトでやったこと）

- **メインメニュー以外では実行しない** … `WinExist("メインメニュー")` で子ウィンドウの存在をチェック。基本処理・特殊処理などが開いている場合はスキップして、デスクトップの誤クリックを防ぐ。
- **設定画面を「楽配くん」として扱わない** … ウィンドウ検出時に「参照用復元」「設定」「Cursor」「.md」を含むタイトルを除外。
- **「今すぐ復元実行」で設定画面を最小化** … 手動実行時に設定UIが前面に残らないようにする。
- **ウィンドウを固定位置に移動** … 親ウィンドウを `WinMove 0, 0` で左上に移動してから座標操作。毎回同じ位置で動作させる。

## 8. このドキュメントの使い方

- 別PCで**復元以外の自動化**（配達資料など）を設計するときの参考にする。
- AIに依頼するときに「楽配くん自動化のノウハウと振り返り.md を読んでから進めて」と伝えると、同じ失敗を避けやすい。
- 新しい自動化が終わったら、ここに追記していくと再利用しやすい。
